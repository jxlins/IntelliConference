# 前后端联调问题修复说明

## 已修复的问题

### 1. ✅ Token 存储问题
**问题**：登录后显示"用户 Token 错误"

**原因**：
- 后端返回: `{ success: true, data: { token: "xxx" } }`
- 前端错误地存储了整个对象，而不是 token 值

**修复**：
```typescript
// 修复前
localStorage.setItem('token', response.data.data)  // 存储的是对象

// 修复后
localStorage.setItem('token', response.data.data.token)  // 存储 token 字符串
localStorage.setItem('username', loginForm.username)     // 同时存储用户名
```

### 2. ✅ 请求 Token 自动携带
**问题**：会议列表等接口没有携带 token

**原因**：每次请求都需要手动添加 token 和 username 到请求头

**修复**：创建了 `src/utils/http.ts` 统一 HTTP 工具
```typescript
// 请求拦截器自动添加 token
http.interceptors.request.use((config) => {
  const token = localStorage.getItem('token')
  const username = localStorage.getItem('username')
  if (token) {
    config.headers['token'] = token
    config.headers['username'] = username
  }
  return config
})
```

### 3. ✅ 会议门户添加退出登录
**位置**：右上角"创建新会议"按钮旁边

**功能**：
- 清除 token 和 username
- 跳转回登录页

### 4. ✅ 会议列表数据获取
**问题**：后端有数据但前端不显示

**调试措施**：
- 添加控制台日志输出响应数据
- 正确处理 MyBatis Plus 分页结构

## 后端 Token 验证机制

### 请求头要求
所有需要认证的接口都需要在请求头中携带：
```
headers: {
  'token': 'xxx',
  'username': 'xxx'
}
```

### 免认证接口
- `/api/intelli-conf/v1/user/login` - 登录
- `/api/intelli-conf/v1/user/has-username` - 检查用户名
- `POST /api/intelli-conf/v1/user` - 注册

### Redis 存储结构
```
Key: short-link:login:{username}
Type: Hash
Field: {token-uuid}
Value: {用户信息 JSON}
TTL: 30 分钟
```

## 调试步骤

### 1. 测试登录流程

1. **打开浏览器控制台**（F12）
2. **访问登录页面**：http://localhost:5174/auth
3. **输入用户名密码，点击登录**
4. **检查控制台 Network 标签**：
   - 找到 `/api/intelli-conf/v1/user/login` 请求
   - 查看 Response：应该返回 `{ success: true, data: { token: "xxx" } }`
5. **检查 Application > Local Storage**：
   - 应该能看到 `token` 和 `username` 两个键

### 2. 测试会议列表

1. **登录成功后自动跳转到会议门户**
2. **打开控制台 Console 标签**
3. **查找日志输出**：
   ```
   会议列表响应: { success: true, data: { records: [...], total: X } }
   加载到的会议数量: X
   ```
4. **检查 Network 标签**：
   - 找到 `/api/intelli-conf/v1/conference/page` 请求
   - 查看 Request Headers：应该包含 `token` 和 `username`
   - 查看 Response：查看返回的数据结构

### 3. 常见问题排查

#### 问题：会议列表为空
**检查点**：
1. **后端数据库中是否有该用户的会议**
   ```sql
   SELECT * FROM conference WHERE create_user = 'your_username';
   ```

2. **后端接口返回了什么**
   - 打开 Network 标签查看响应
   - Console 中查看日志："加载到的会议数量: X"

3. **后端是否正确过滤用户的会议**
   - 检查后端 `ConferenceService.pageConference()` 方法
   - 是否根据当前登录用户过滤数据

#### 问题：Token 错误
**检查点**：
1. **LocalStorage 中是否有 token 和 username**
2. **请求头是否正确携带**（Network > Headers）
3. **Redis 中是否有该用户的登录信息**
   ```bash
   redis-cli
   HGETALL short-link:login:your_username
   ```

#### 问题：跨域错误
**解决方案**：
- 前端使用 Vite 代理，不应该有跨域问题
- 检查 `vite.config.ts` 中的 proxy 配置
- 确保后端运行在 8080 端口
